# Migrating from crudcrate 0.9.x to 0.10.0

0.10.0 moves the workspace to SeaORM 2.0 (SeaQuery 1.0, SQLx 0.9). Your
application must upgrade to `sea-orm = "2.0"` in the same step: crudcrate's
public API exposes SeaORM types and the derive macros emit `sea_orm::` paths,
so both crates need to resolve to the same SeaORM major version. If you need
to stay on SeaORM 1.x, stay on crudcrate 0.9.x.

## TL;DR

| Scenario | Action |
|---|---|
| Entities use the classic `DeriveEntityModel` format | Bump both versions, then follow the [SeaORM 2.0 migration guide](https://www.sea-ql.org/blog/2026-01-12-sea-orm-2.0/) for your own SeaORM usage. crudcrate attributes are unchanged. |
| Code calls `db.execute(backend.build(&stmt))` | Replace with `db.execute(&stmt)` (SeaORM 2.0 builds the statement internally). Raw `Statement`s go to `execute_raw`. |
| Hand-written `resolve_joined_filters` using `ColumnRef::TableColumn` | That variant is gone in SeaQuery 1.0. Use `crudcrate::table_column_ref(table, column)`. |
| Entities migrated to the SeaORM 2.0 dense format (`#[sea_orm::model]`) | Works out of the box, see below. |

## What changed inside crudcrate

- **Batch create uses a single multi-row `INSERT ... RETURNING`** on Postgres
  and SQLite (>= 3.35). MySQL keeps the previous per-row insert inside the
  transaction. Semantics are unchanged: response order matches input order,
  all-or-nothing on failure, duplicate keys map to 409, `?partial=true` is
  unaffected. The `sqlite` feature now enables SeaORM's
  `sqlite-use-returning-for-3_35`.
- **New public helper** `crudcrate::table_column_ref(table, column)` builds a
  table-qualified `ColumnRef` (SeaQuery 1.0 restructured the `ColumnRef` enum).
- No changes to `#[crudcrate(...)]` attributes, routes, filtering, sorting,
  pagination, hooks, or the `CRUDResource` trait surface.

## Dense entity format

Entities written in SeaORM 2.0's dense format derive `EntityToModels` the same
way as classic entities:

```rust
#[sea_orm::model]
#[derive(Clone, Debug, PartialEq, DeriveEntityModel, EntityToModels)]
#[sea_orm(table_name = "authors")]
#[crudcrate(generate_router, api_struct = "Author")]
pub struct Model {
    #[sea_orm(primary_key, auto_increment = false)]
    #[crudcrate(primary_key, exclude(create, update), on_create = Uuid::new_v4())]
    pub id: Uuid,

    #[crudcrate(filterable, sortable)]
    pub name: String,

    #[sea_orm(has_many)]
    pub books: HasMany<super::book::Entity>,
}
```

Relation wrapper fields (`HasMany<..>`, `HasOne<..>`, `BelongsTo<..>`) do not
appear in the generated Create/Update/List models or API responses. To expose
related entities through the API, keep using crudcrate `join(...)` fields.
crudcrate's join loading does not use SeaORM 2.0's Entity Loader; the
reasoning is documented in the relationships chapter.

## SeaORM 2.0 changes most likely to touch your code

These are SeaORM changes, not crudcrate changes, listed here because every
crudcrate user hits SeaORM directly:

- `use sea_orm::ExprTrait;` is required for `.eq()`, `.like()`, `.add()` and
  friends on `Expr`. Note the blanket impl also makes a bare `.min()`/`.max()`
  method call ambiguous with `Ord` wherever `ExprTrait` is in scope; use
  `std::cmp::min`/`max` there.
- `execute`/`query_one`/`query_all`/`stream` take SeaQuery statements directly;
  the raw-SQL variants are renamed `execute_raw`/`query_one_raw`/
  `query_all_raw`/`stream_raw`.
- `Iden::unquoted()` returns `&str` instead of writing into a buffer.
- Postgres auto-increment columns are created as
  `GENERATED BY DEFAULT AS IDENTITY` instead of `serial`.
- MSRV 1.85, edition 2024.
